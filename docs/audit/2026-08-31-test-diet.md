## Method

1. Baseline: `pytest -n 4 --cov=agent_takkub --cov-context=test --cov-report=json` over the full suite (PYTHONPATH pinned to this worktree's `src/`, `pytest-cov`/`coverage` installed to a scratch `--target` dir so the shared venv was never touched).
2. **Coverage-subset parametrize check**: grouped every parametrized test by its base name (nodeid with the `[...]` stripped) and looked for cases whose covered-line set was byte-identical to a sibling case's — the strongest, cheapest signal for "6 parametrize values hitting one branch." **Result: zero groups.** A looser near-identical-subset pass (same base name, ≤5% line-count delta) also found **zero**. This suite's parametrize cases each exercise genuinely distinct branches; there is no mechanical parametrize-collapse opportunity here.
3. **General coverage-subset pass** (any two tests in the same file, not just same-function parametrize): found 4,921 raw subset-candidate pairs. Per the audit rule ("assert แบบเดียวกัน (อ่านโค้ดยืนยัน)"), a subset relationship alone is not proof of redundancy — a subset is expected any time one test's branch is a strict prefix of another's (e.g. a happy-path test vs. an error-path test that shares setup). Verifying 4,921 pairs by hand was not feasible in this session; see "Not done" below.
4. **Exact-AST-body duplicate scan** (own approach, not in the original task spec — a stronger, cheaper signal than coverage-subset for real copy-paste): hashed every `def test_*` body (module/class-normalized AST dump, docstring stripped) across all 479 files. Found **11 groups, 13 candidate functions**. Manually read every group's source:
   - **1 group (4 functions) was a false positive**: `test_agent_role_files_have_{browser,host_destructive,host_network,pip_editable}_guard.py` — four parallel guard files that each parametrize the same check-shape over a different module-level `SECTION` constant (different required prose per guard). Identical AST, different guarded content. **Kept, not a duplicate.**
   - **9 groups (9 functions) were real, provable duplicates** — same call sequence, same literal assertions, in the same file, no distinguishing setup. Cut (see table).
   - **1 group (1 function) was a real code duplicate but declined** — see "Declined despite duplication" below.

## `agent_takkub.core` V2-authority marker (task step 4) — not done, audit disagrees with the premise

The task assumed `agent_takkub.core` (131 files) is a parked "V2 package" not yet switched to authority (#362) and asked to mark its ~1,156 tests `pytest.mark.v2`, excluded from the default gate.

Investigation found this premise doesn't hold:
- `agent_takkub.core` has 17 subpackages (`accounts`, `brain`, `capabilities`, `context_sources`, `contracts`, `conversation`, `migration`, `model_catalog`, `models`, `providers`, `resilience`, `routing`, `scheduling`, `secrets`, `storage`, `versioning`) — broad shared infrastructure, not a single speculative brain module.
- **26 live top-level modules** import directly from `agent_takkub.core` today, including `cli.py`, `doctor.py`, `config.py`, `orchestrator.py`, `provider_config.py`, `role_models.py`, `skill_policy.py`, `resource_governor.py` — this is load-bearing shared code, not dead/parked code.
- "#362 / V2 authority" (docs cross-checked: `docs/architecture/v2-workspace-flow.md`, `docs/plans/2026-08-23-master-dev-plan.md`) is actually a narrow, already-partially-live feature — a `TAKKUB_V2_AUTHORITY` dual-write flag concentrated in `core/storage/v2_authority.py` + `core_v2_settings.py` — not "the whole `core/` tree is unauthoritative." The team's own memory records dual-write soak already running with drift = 0.

Excluding all of `agent_takkub.core`'s tests from the default gate on this premise would have silently blinded the default dev gate to regressions in secrets management, provider config, context sources, and other modules 26+ live files depend on today. **Declined — flagging back to Lead/user**: if there is a genuinely-parked subset of `core/` worth isolating behind a marker, it is narrower than the whole package (likely limited to `core/brain`'s speculative orchestration logic, or specifically `core/storage/v2_authority.py` + `core_v2_settings.py`) and needs a scoped decision, not a blanket one.
