## Coverage limits and release follow-up

The changed test suite passing is insufficient for this batch: tests miss real provider-total reconciliation, mutable SQLite WAL, retention with partial historical rescans, concurrent writers, actual remote no-write behavior, main-thread slow I/O, worker destruction and direct spawn recovery paths. These should become regression tests with each fix; this review did not modify production or test files.

Explicit persistent override behavior was also checked: `set_current('full')` does **not** clear an active solo override, and a subsequent assign without `--team` does not clear it either. This is documented intentional behavior and is not counted as a separate bug; the operator must use `team clear-override`. `auto`'s new `suggest_team_size` helper has no production caller found by `rg`; its runtime recommendation flow and preset UI are not proven by this logic-only batch.

The mtime warning is an on-demand signal, not a week-long monitor. **This review does not certify `v1_only_write=0` plus `drift=0` for one week on dev and prod.** Keep the 2.1.0 archive/move gate separate from this 2.0.x release and gather that evidence after fixing the detection gap.

**Recommendation:** fix HIGH items, add the missing targeted regressions, then re-run targeted tests and the normal CI/release gate. No push/commit was performed.
