# #168 — Knowledge-distillation loop: auto-capture teammate learnings on done

## Decision: extended existing system, did not build a new one

Two systems already did almost exactly this:

1. **`role_memory.py`** — per-`(project, role)` learned notes, auto-appended on
   `done(failed=True)` via `append_failure_entry`. Scoped to one role's own
   memory and injected into that role's next spawn prompt. Not a fit here:
   #168 asks for durable knowledge from **every** done (not just failures)
   in a **project-wide** store, and role_memory's per-role file is already
   deliberately narrow (its own docstring: "seeding is best-effort... Lead is
   intentionally excluded").

2. **`vault_mirror.py`'s `distill_session_facts`** (Phase B, already shipped)
   — this is the real match. On every `takkub done` / `end-session`, it
   already: filters notes for "durable" signal (`_is_durable_fact` — fix/bug/
   decision/pattern/refactor keywords, Thai included), scrubs control bytes
   and frontmatter-injection (`_scrub_note`), and idempotently appends a
   one-line entry into a curated `## Decisions & Learnings` section of
   `01-Projects/<project>.md`.

   The problem: it only runs when `_resolve_vault_dir()` finds a configured
   Obsidian vault (`$TAKKUB_VAULT_DIR` or `~/second-brain`). Most cockpit
   installs have no vault, so most installs get **zero** distillation today
   — exactly the gap #168 describes ("ความรู้ที่ได้มากระจัดกระจาย ไม่มีใครกลับไปอ่าน").

**Chosen approach:** add `distill_to_knowledge_base()` as a sibling function
in `vault_mirror.py`, reusing `_is_durable_fact` / `_scrub_note` verbatim, and
call it unconditionally from `orchestrator.py::_save_decision_note` — outside
the `if vault is not None:` guard — so it fires regardless of whether a vault
is configured. This is "extend the existing system" rather than a new
subsystem: same filter, same scrub, same call site, same best-effort contract
as the code already sitting next to it.

## What changed

- `src/agent_takkub/vault_mirror.py`
  - `distill_to_knowledge_base(project, role, note, runtime_dir, *, now=None) -> bool`
    — writes a durable note as one bullet into `runtime/knowledge/<project>.md`.
  - `knowledge_base_enabled()` — opt-out gate, `TAKKUB_KNOWLEDGE_BASE=0/false/off/no`
    (env var, same pattern as `settings_management/feature_flags.py`'s
    `TAKKUB_SETTINGS_UI`). Default: enabled.
  - `knowledge_base_path()`, `_kb_header()`, `_cap_knowledge_base()` — size-capped
    flat markdown file, oldest entries (topmost bullets) dropped first once it
    exceeds `_KB_MAX_BYTES` (12,000) or `_KB_MAX_ENTRIES` (150) — same
    "drop-oldest" strategy `role_memory.py`'s `_curate_text`/`_trim_oldest_bullet`
    already uses for the same reason (this file can get read again later, so an
    unbounded file becomes a silent token-cost sink).
- `src/agent_takkub/orchestrator.py`
  - imports `distill_to_knowledge_base`.
  - `_save_decision_note` calls it right after the local `runtime/sessions/`
    write, **before** (and independent of) the vault branch — wrapped in its
    own `try/except Exception: pass` so a write failure can never break the
    `done()` report path it rides alongside (requirement #2).

## How the 5 scope requirements are met

1. **Reusable-conclusions only, not the whole report** — gated by
   `_is_durable_fact`; routine "ok"/"tests passed" notes never get written.
   One condensed bullet (`- \`iso\` **role** — note, capped at 300 chars`) per
   done event, not the full session markdown.
2. **Never slows/breaks `done()`** — best-effort try/except at the call site,
   mirroring the existing `graft_autobuild`/`task_ledger` hooks right next to
   it in the same function; verified by
   `test_done_flow_never_raises_when_knowledge_base_write_fails`.
3. **No unbounded growth** — `_cap_knowledge_base` FIFO-trims oldest bullets
   past the byte/entry budget on every write.
4. **Opt-out, provider-neutral** — `TAKKUB_KNOWLEDGE_BASE=0` disables it
   cockpit-wide; the call site is `_save_decision_note`, which every
   provider's `done()` already funnels through (no claude-only branch).
5. **No sensitive data** — reuses `_scrub_note` (same scrubbing the
   already-shipped vault distill relies on: strips control/escape bytes,
   defuses a leading `---` frontmatter delimiter, caps length). No new
   secret/path redaction was added — this matches the existing accepted
   threat model for agent-authored done-notes (agents are expected not to
   paste credentials into a `done` note) rather than inventing a new one
   for this feature alone. **Not auto-injected into any spawn prompt** —
   unlike `role_memory.py`, this file is a passive record, not something a
   future teammate cold-reads automatically. If auto-injection is added
   later, the redaction question should be revisited then.

## What was deliberately left out

- No L2 archive for trimmed entries (unlike `role_memory.py`'s #151) — this
  is meant to stay a lightweight recent-knowledge scratchpad; the untrimmed
  history already lives in `runtime/sessions/` and (if configured) the vault.
- Not wired into `bm25_search.py` / `takkub search` — not asked for, easy
  follow-up if the file grows big enough to want ranked search.
- Not read/injected at spawn time for any role — narrow on purpose per the
  task's "อย่าทำใหญ่" instruction; a future issue can decide who reads it and
  how (Lead only? every role? on-demand via a CLI flag?).
