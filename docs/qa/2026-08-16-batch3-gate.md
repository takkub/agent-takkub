Root cause: this test spins up a real installed venv build and asserts that `_render_lead_context()`'s output rewrites the bare `` `docs/lead/patterns.md` `` reference (which only resolves from a dev checkout cwd) to an absolute staged path under `ASSETS_ROOT/docs/lead/`. So on the installed build:
- `has_bare_reference` correctly comes back `False` (no bare ref present — good)
- `has_rewritten_reference` also comes back `False` because there was never a `docs/lead/patterns.md` substring in root CLAUDE.md to rewrite in the first place

This is the exact class of drift the task's item 3 asked to check ("ไม่มีที่ไหนในโค้ดที่อ่าน root CLAUDE.md แล้วคาดหวังเนื้อหาที่ย้ายออกไปแล้ว") — found one. `lead_context._build_lead_context_text`'s rewrite logic (lines ~342-351) itself is fine (it still string-replaces any `docs/lead/` substring it finds, including inside role-and-workflow.md's own content if that gets inlined — but it doesn't inline role-and-workflow.md, so the one-hop reference is never touched). The regression is in the **test's premise**: it directly reads root CLAUDE.md's *own* text for the patterns.md substring, which no longer exists there post-diet.

Not a functional break for a real Lead (role-and-workflow.md is a doc the diet's own pointer sends Lead to read, and *that* file's `docs/lead/patterns.md` references are unaffected — Lead reads them relative to repo root in a dev checkout, or would dangle in an installed build exactly like before, just one file removed from the entry point). But since installed-mode Lead now reads role-and-workflow.md too, and that file's own `docs/lead/patterns.md`/`docs/lead/cli-reference.md` refs are **not rewritten** by `_build_lead_context_text` (only root CLAUDE.md's text goes through the rewrite), an installed-mode Lead who opens role-and-workflow.md would hit dangling relative refs there — same class of bug the original fix (#commit 7080ec9-era) was meant to close, now reopened one hop downstream.

**Fix needed**: either (a) update the test to check role-and-workflow.md's staged/rewritten reference instead of root CLAUDE.md's, or (b) extend `_build_lead_context_text`'s rewrite (or a parallel step) to also rewrite `docs/lead/` refs inside the shipped role-and-workflow.md content for installed builds — (b) is the real fix since it's the actual functional gap; (a) alone would just paper over it.
